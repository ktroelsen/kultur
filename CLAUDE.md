# Kultur – noter til Claude

- Konceptet står i `docs/koncept.md`. Læs det før større ændringer, og hold det opdateret.
- Samme stil og teknologi som Læs højt (`ktroelsen/read`): ASP.NET Core minimal API (.NET 10) + React/Vite/Tailwind PWA i `web/`.
- Backend: `dotnet build -c Release -warnaserror` og `dotnet test` skal være grønne. I Git Bash: brug `-warnaserror`, ikke `/warnaserror`.
- Frontend: `npm --prefix web run lint` og `npm --prefix web run build`.
- UI-tekster er på dansk; kode og kommentarer på engelsk.
- Ingen database: data er JSON-filer i `App_Data`, pr. bruger under `App_Data/users/{id}/`. App_Data skippes ved deploy, så data overlever.
- Kilder er en fast liste i koden; klienten vælger en nøgle, aldrig en URL. Hent kun fra sider, hvis brugervilkår tillader det. Omtaler gengives som stjerner + kilde + link, aldrig anmeldelsens tekst.
- Kilder implementerer `IEventSource` (`src/Kultur.Api/Scan/`) og registreres i `Program.cs`; en kilde uden nøgle springes over, og en fejlende kilde stopper ikke de andre. Arrangementer normaliseres til `CultureEvent` med id `"{kilde}:{kildens id}"` og samles i `EventCatalog` (`App_Data/events.json`); fortidige fjernes ved hver scanning. Reaktioner (Gem/Måske/Nej tak) og sidste besøg ligger i `UserData`.
- Knapperne lærer (`Lessons`, `App_Data/users/{id}/learning.json`): Gem/Måske giver plus til kunstner, genre (og sted ved Gem); "Nej tak" spørger hvorfor – `Date` (kan ikke den dag: kun denne dato, intet læres), `Place` (kun denne dato, minus til stedet) eller `Event` (minus til kunstner/genre, og hele serien skjules, også datoer fundet senere). En serie er `CultureEvent.Series` (kildens gruppe, fx Original Talks' `event_group_id`) eller titlen uden tegnsætning (`Series.KeyOf`). Hvert arrangements bidrag gemmes for sig (`Applied`), så det kan trækkes præcist tilbage; summen pr. emne holdes inden for −2…+2 og bruges kun, hvor emnet ikke er vurderet under Smag.
- Original Talks (`OriginalTalksSource`): ingen API; `sitemap.xml` → hver forestillings side → event-objekterne i Next.js' `self.__next_f.push`-payload. Kun fakta (titel, taler, tid, sted, pris) + link – ingen beskrivelser eller billeder (deres handelsbetingelser forbeholder indholdet). Datoer solgt via Ticketmaster springes over (dem har vi fra Ticketmaster). Ca. 67 kald pr. scanning, 1 pr. sekund.
- Zoner (`Zones`): 1 Storkøbenhavn, 2 resten af Danmark, 3 udlandet.
- Smag (`src/Kultur.Api/Taste/`): emner (`Topic`: kategori, genre, kunstner/hold, sted) vurderes `Never`…`Very` på siden "Smag", ét ad gangen (`GET /api/taste/next`). `TasteModel.FitOf` giver hvert arrangement point (kunstner vægter 3, genre 2, sted/kategori 1), skjuler det ved "aldrig" (medmindre en kunstner, man kan lide, er med) og finder begrundelsen. "Til dig" sorteres efter zone og point; efter `RatingsBeforeZoneThresholds` vurderinger kræver zone 2 og 3 flere point (`MinScore`).
- Claude (`Ai:ApiKey`, secret `ANTHROPIC_API_KEY`) bruges i dag til løb (`RunsSource`): én gang om ugen (`Runs:IntervalDays`, tilstand i `App_Data/runs.json`) slår Claude hvert løb i `Runs:Races` op med websøgning (højst `Runs:MaxSearchesPerRace` søgninger pr. løb, fire løb ad gangen) og svarer med JSON: datoer, officiel side, tilmeldingsstart (→ `SaleStart`) og en tilmeldingsnote (→ `Note`). Løbets navn er en "kunstner", så det kan vurderes under Smag. Senere også rangering, profil og udtræk fra HTML. Uden nøgle er AI slået fra.
- Natlig scanning: `.github/workflows/scan.yml` kalder `POST /api/scan` med `X-Scan-Key` (`Scan:Key`, secret `KULTUR_SCAN_KEY`); en logget-ind bruger må også starte den. IIS genbruger app-poolen, så ingen baggrundstjeneste.
- Hosting er Simply (IIS, 32-bit, shared, self-contained win-x86) på kultur.kaspert.dk – samme opsætning som read.kaspert.dk.
- Se `docs/simply-deploy.md` for secrets og første deploy.
- Deploy synkroniserer hele sitet og sletter alt, der ikke er i build'et (undtagen `App_Data` og `logs`). `SIMPLY_WEBDEPLOY_SITE` afgør, hvilket site der overskrives – ret aldrig den eller `_URL` uden at brugeren bekræfter værdierne. `deploy.yml` afviser andre sites end `kultur.kaspert.dk` – fjern ikke det værn.
- Hemmeligheder kommer fra GitHub Secrets (environment `Production`) → `appsettings.Production.json` i deploy-workflowet. Aldrig i repoet. Her hedder Web Deploy-adgangskoden `SIMPLY_WEBDEPLOY_PASSWORD` (korrekt stavet – i read-repoet er den stavet `PASSEORD`), mens `CLAUDE_CODE_0AUTH_TOKEN` er stavet med 0 som i read. Navnene skal matche de oprettede secrets – ret dem ikke uden at brugeren bekræfter.
- Simplys firewall (ModSecurity) afviser curl med 455; brug `curl -A "Mozilla/5.0" …` ved røgtest.
- Arbejdsgang: branch → PR → CI grøn → merge → auto-deploy.
